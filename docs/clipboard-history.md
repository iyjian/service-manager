# Clipboard history

Clipboard history is available on macOS and Linux while Service Manager is running.
Open it with **Control + Option + V** on macOS or **Ctrl + Alt + V** on Linux.
Settings > Shortcuts lets you record a replacement shortcut, restore the default,
or disable collection and the global shortcut. Changes take effect on Save.
A shortcut conflict leaves the previous shortcut active.

The floating panel shows the latest 20 distinct text or PNG image entries.
Use Up/Down and Enter to select and paste, Escape to dismiss, Delete to remove
the selected item, or Clear all to erase history. Clicking an entry pastes immediately.
On macOS the panel opens beside the text insertion caret and stays inside the
current display. If the target app does not expose its caret position, it uses
the mouse location captured when the shortcut was pressed instead. The original
input control and selection are restored before pasting; focus remains in that
control with the caret after the inserted content, ready for continued typing.
Escape restores the original selection without pasting. Clicking outside
dismisses the panel without moving focus back from the clicked application.
Images larger than four million pixels and entries larger than 2 MiB are skipped.
Clipboard sampling runs every 600 ms; very brief clipboard changes may be missed.
Rich text is stored as plain text. Files and other clipboard formats are not stored.
Password-manager content marked concealed, transient or autogenerated is skipped;
ordinary copied secrets without these markers cannot be identified reliably.

On macOS, automatic paste requires Accessibility permission for Service Manager
in System Settings > Privacy & Security. A bundled native helper captures the
focused control and selection and posts paste directly to that application;
it does not use AppleScript or require Automation permission. Permission or target
errors are reported before opening the picker. A failed paste is not reported as
a successful copy operation, and does not display a modal over the destination.
On Linux, automatic
paste currently requires X11 and an existing `xdotool` installation; nothing is
installed automatically. Linux positions the panel at the invocation's mouse
location because xdotool does not expose text caret bounds. Unsupported sessions
(including Wayland) report that automatic paste is unavailable before opening.
Global shortcut support also depends on the desktop environment.

History and shortcut preferences are stored only in
`clipboard-local/history.json` inside the current Electron userData profile.
Development and packaged apps use their existing separate profiles. This file
is not part of Notes, S3 sync or configuration exports. It is written atomically
with owner-only permissions and encrypted with Electron safeStorage when a
secure OS backend is available. Otherwise it uses a local, unencrypted file.
Disabling collection preserves existing history. Clear all removes saved entries,
but does not clear the system clipboard. An unreadable history file is preserved
and the feature reports an error rather than overwriting it.

Windows continues to use native Win + V; Service Manager does not monitor its clipboard.

## Building and verification

macOS builds compile `src/main/core/native/clipboard-macos.m` using the system
Clang and macOS SDK (Xcode Command Line Tools). The helper is universal arm64/x64
and packaged outside ASAR so it runs without developer tools on end-user machines.
No additional npm dependency is needed. Other platforms skip this build step.
Caret coordinates, process ID and operation status are the only helper output;
target text is never read, logged or sent to the picker.
