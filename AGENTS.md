# AGENTS Guide

## Purpose

Service Manager is an Electron + TypeScript desktop app for managing remote development hosts over SSH.

It supports two host-scoped runtime resources:

- Forwarding rules: SSH local port forwards managed in-app.
- Services: remote processes managed through `systemd --user` transient units.

It also supports a local Mihomo proxy runtime backed by a Clash-format subscription.

## Non-Negotiable Rules

- Keep the app consistent in English UI tone, modal host editing, grouped host lists, and `tsc` build-to-`dist` workflow.
- Use `ssh2` for SSH connections and remote command execution; do not shell out to system `ssh`.
- Use `@kubernetes/client-node` for Kubernetes operations; do not shell out to `kubectl` or another system command.
- Keep `asn1` explicitly declared as a dependency.
- Do not install dependencies yourself. If dependencies are needed, stop and ask the user to run `pnpm install`.
- When Kubernetes/xterm dependency versions change, update the manifest and require the user to run `pnpm install` before build or runtime work resumes.
- Important changes must update both `README.md` and `AGENTS.md` when they affect features, architecture, runtime behavior, command flow, data model, limits, or developer workflow.
- Keep packaged and unpackaged runtime data isolated: `pnpm dev` and `pnpm start` must never read, copy, migrate, or fall back to the installed application's Electron data profile.
- Prefer incremental changes with tests.

## Runtime Model

Hosts:

- Host creation/editing requires only name and SSH connection info.
- Forwarding rules and services are optional and start empty.
- Jump servers are configured inside Add/Edit Host as an ordered multi-hop chain.
- Private-key auth supports pasted key content and imported key files; import should default to `~/.ssh` when possible.
- The Hosts header shows the total local Service Manager Memory in GB. It aggregates all Electron `app.getAppMetrics()` processes and local Mihomo RSS when running, refreshes every five seconds only while Hosts is active, and replaces the old host/tunnel/service aggregate. Remote SSH services are excluded, as is system-wide memory.
- Automatic Service polling runs only while Hosts is visible and is Host-scoped: one request owns all requested Service keys, waits behind any in-flight Service mutation, performs one combined remote `list-units`/`show` status exec after the cached systemd preflight, then fences result validation, PID/forward application, at most two Host writes, and one batch status event against shared Host configuration changes. At most four Hosts run their remote queries concurrently; returning to Hosts triggers an immediate refresh, and transient remote `starting`/`stopping` observations remain eligible for the next poll.
- Preserve a Service PID across Host edits or cloud apply only when its start command, exposed port, target SSH endpoint/authentication, and ordered jump-host chain are unchanged. An endpoint change must clear the device-local PID before the new endpoint is polled.
- Service and forwarding status events update their exact visible Host row after coalescing same-frame changes. A missing or inconsistent row triggers at most one coalesced full Hosts render; collapsed Hosts remain unexpanded and are not rebuilt for ordinary status changes.
- Host collapse/expand updates only the targeted Host panel. Leaving Hosts cancels its polling/frame ownership, clears its rendered Host/log DOM, and restores the same UI from the retained lightweight Host views on return.

Notes:

- Notes expose only Name, Content, and Language in the editor. Internal Tags remain part of the durable Note model for sync, search, and conflict recovery but are not displayed or editable. Newly created Notes default to Rich Text; keep Rich Text first and Markdown second in the Language selector. Language uses the compact Kubernetes-style button/search/listbox treatment, filters labels and useful aliases without reordering, exposes the selected state, and supports pointer, Arrow, Home/End, Escape, outside-click, and focus-leave behavior. Markdown, Bash, JavaScript, TypeScript, SQL, JSON, and YAML use CodeMirror 6 with parser-backed syntax highlighting, Markdown fenced blocks recognize Bash, JavaScript, TypeScript, SQL, JSON, and YAML, and Plain Text remains unstyled. Rich Text uses Tiptap and persists only the shared validator's canonical Tiptap JSON, never renderer HTML; canonical hard breaks retain Tiptap's strictly validated inline marks so imported styled `<br>` elements round-trip without falling back. It follows the running Novel editor's platform-native system sans stack and `prose-lg` typography instead of forcing one packaged family across operating systems. Rich Text Code blocks use the exact local 37-language Lowlight `common` set. The active or hovered Code block exposes a compact opaque language pill overlaid in its top-right corner above the code text; do not reserve a control row or otherwise shift the normally padded first source line, and allow an unusually long line to pass beneath the pill. Its searchable list preserves useful aliases and supports pointer, Arrow, Home/End, Enter, Escape, outside-click, focus-leave, and `Alt+F10`; no language attribute means `Auto`, while a supported explicit attribute always wins over detection. With a caret or partial `TextSelection` wholly inside one non-empty Code block, the first `Ctrl/⌘+A` must select exactly that node's code text and a fresh second press must fall through to ProseMirror's complete-document Select All. Keyboard-repeat events after the first press must retain the block selection; cross-block, NodeSelection, CellSelection, empty-Code, and ordinary prose cases must retain the default behavior. Bound automatic editor highlighting to 10,000 characters, explicit-language editor highlighting to 50,000, and total PDF highlighting to 100,000 characters; PDF applies the same explicit-first behavior, while Markdown file export remains source-oriented and unhighlighted. Non-empty text selection outside a Code block opens a floating formatter with the full Text/Heading 1–3/To-do/Bullet/Numbered/Quote/Code block selector, safe link editing, inline math, Bold/Italic/Underline/Strike/Inline Code marks, and independent text/highlight colors; a selection intersecting a Code block must keep that formatter hidden, and it must not expose Ask AI. Typing `/` opens a Novel-style block menu for Text, To-do List, Heading 1/2/3/4, Bullet List, Numbered List, Quote, Code, Table, Image, and File; `/heading4` inserts a canonical level-four heading without adding it to the selection formatter, and the menu must not offer feedback, YouTube, Twitter, or any AI action. Keep a compact Trilium-style six-dot block handle immediately left of the first line of the active top-level Rich Text block or the block under the pointer in the left writing gutter, with a transparent borderless rest state and only muted 2px dots visible. Clicking it must open the same keyboard-accessible command menu against the captured block without inserting slash text and initially select the captured block's actual Text, Heading, list, Quote, Code, Table, Image, or File format; dragging it must move the complete top-level block through ProseMirror's native slice/drop transaction and visible drop cursor so undo/redo and schema ownership stay intact. A multiline Code block must own exactly one handle anchored to its first line and must never follow its internal caret lines. `/table` inserts a `3×3` table with a Header row. Keep table nodes, cell/multi-cell selection, keyboard behavior, copy/paste, undo/redo, commands, and resize ownership in official Tiptap TableKit; the renderer may add only a compact Novel-style row/column/table hover overlay that dispatches official commands. Preserve TableKit's cell Tab behavior and expose `Alt+F10` plus `Shift+F10` as the keyboard path into those overlay controls. Tables use theme tokens in Light/Dark mode, a 96px minimum column width, contained horizontal scrolling, and bounded canonical span/rectangular-geometry validation. To-do items retain a validated boolean checked state; their custom checkbox must inherit the surrounding Rich Text typography and use a font-scaled, optically corrected Novel-style offset so its center stays on the first text line across the supported 12–24px font range. Suppress the generic empty-editor prompt for an empty To-do and preserve standard Enter/Tab/Shift-Tab list behavior. CodeMirror and Tiptap share one device-local Light/Dark preference and default to Light.
- Keep the sidebar workspace search distinct from active-Note find. `Ctrl/⌘+F` must open one compact top-right editor find bar with case-insensitive literal matching, all-match plus active-match highlighting, caret-relative initial selection, wrapping Previous/Next, `Enter`, `Shift+Enter`, and `Escape`. CodeMirror searches its authoritative source. Rich Text searches only editable text in text blocks, may cross adjacent inline-mark boundaries, and must not cross block/hard-break/inline-atom boundaries or match image/attachment metadata. Do not create a Tiptap text selection for find highlights or trigger the selection formatter. - Keep `service-manager-{hostId}-{serviceId}.service` for creation when no existing Service ID match is loaded. Do not rename or migrate existing units.
- Treat multiple matching units for one Service ID as an explicit ambiguity error and do not mutate a candidate automatically.
- `systemd active` means running; missing/inactive units mean stopped.
- Start should return once `MainPID` is available; port checks and forwarding are post-start work.
- Do not use `systemd-run --collect`; failed/exited units must remain inspectable.
- Intentional stop should settle to `stopped`, even if systemd briefly reports failed due to termination signal.
- Service `start`, `stop`, background `refresh`, and `delete` must be serialized per host/service key.
- Categorize systemd preflight failures as SSH timeout/failure, missing tools, unavailable user-manager D-Bus, tooling/user-manager check failures, or linger failures. Retry only a transient user-manager transport or D-Bus failure once; never mask the final categorized error.

Logs:

- Open logs from the service name in the list.
- Read logs with `journalctl --user` for the current unit invocation.
- Preserve stdout/stderr ordering as a single terminal-like stream.
- Render ANSI colors, auto-refresh, auto-scroll toggle, older-line loading, search, and filter.
- Log dialog is read-only and must catch failures without uncaught renderer promises.
- Local runtime diagnostics for later intermittent SSH/systemd troubleshooting are written under Electron `<userData>/logs/runtime.jsonl`. Rotate the active file to `runtime.previous.jsonl` before it exceeds 1 MiB, retaining only those two files. Store only a redacted, safe diagnostic scope and context; omit or redact credentials, keys, tokens, URLs, and command text.

## Safety Requirements

- Renderer must escape dynamic HTML derived from host, service, tunnel, log, or error data before injecting into the DOM.
- Renderer runtime failures should be surfaced through page toasts instead of failing silently.
- Main process must log top-level `uncaughtException`, `unhandledRejection`, renderer-process exits, and IPC broadcast failures.
- Runtime diagnostic logging must be best-effort and must never interrupt lifecycle handling. Redact sensitive error/context material before local persistence.
- Initialize `@sentry/electron/main` synchronously before Electron `ready` and initialize `@sentry/electron/renderer` before renderer application modules read the DOM. Sentry is error-only: disable minidumps, screenshots, sessions, breadcrumbs, network/console/context collection, local variables/source context, logs, metrics, tracing, profiling, attachments, and client reports. Renderer events travel through the official Electron IPC transport and the main process owns the DSN and bounded final flush.
- Every Sentry event must pass the shared strict allowlist. Retain only a safe generated error value, validated exception type, static process/scope tags, release/environment, and app-relative stack filenames/functions/line numbers. Never send Notes names/content, DOM text, IPC payloads, runtime-log context, Host/Kubernetes resource names, Secret values, S3/SSH/Kubernetes/LLM/Trilium endpoints or credentials, URLs/query/header/body/cookies, home paths, console arguments, screenshots, minidumps, or attachments.
- S3 AK/SK, Sync Encryption Key, the optional LLM Token, and a transient Trilium ETAPI Token may enter renderer state only through their designated password inputs and narrow IPCs. Persisted S3/LLM secrets remain protected by `safeStorage`, and ordinary reads expose only presence. Keep hydrated values masked except for the one eye-selected field, and re-mask them on Save, Sync, or dialog close. Never persist a Trilium Token or importer Endpoint configuration, and never include either input in settings, runtime logs, diagnostics, or error messages; imported Note content is ordinary shared content and may itself contain Trilium URLs. Neither plaintext nor protected secret material may enter v4 shared payloads; the Sync-Key identity is only a non-secret linkage digest. Durable shared app data may leave the machine only inside authenticated encrypted v4 manifest/Note/Note-tree objects; the plaintext v4 head contains only integrity/linkage metadata. LLM settings and responses are never shared data.
- Kubeconfig bytes, absolute source paths, stable-ID source mappings, tokens, client certificates/keys, client transport/VNC handles, and terminal/port-forward/VNC credentials stay in the main process and never cross renderer IPC or persist to disk. Terminal output may be transiently relayed but must never be persisted to main-process state, disk, settings, or logs; retained xterm views and the bounded pre-bind bridge are renderer-memory-only.
- Kubernetes Secret `data`/`stringData` must be absent from list/cache/diagnostic/settings data. Decode `secretKeyRef` and `envFrom.secretRef` only through a narrow request in the main process for the active drawer; keep its result bounded and locally searchable, clear it when that drawer closes or changes, and never cache, persist to settings, log, diagnose, or write it to disk.
- SQL API origins, Tokens, protected/derived credentials, statements, results, Saved Query contents, usernames, and remote response bodies must not enter runtime diagnostics, Sentry, screenshots, test fixtures, or S3 shared data. The renderer receives only the narrow SQL view/API contracts and text-safe remote errors.
- Dialog open/close paths must be idempotent.
- Missing remote `systemd --user` support must fail explicitly with setup guidance; never silently switch to an unmanaged process model.
